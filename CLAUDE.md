## Git branch naming

Always create Git branches with clear, descriptive names directly relevant to the work being performed. Use the format `type/short-description` (e.g., `feat/user-authentication`, `fix/mobile-navigation`, `refactor/api-handlers`). Branch names should accurately reflect the specific task, feature, or bug being addressed. Never use random, generic, autogenerated, or meaningless branch names. Apply this rule consistently to all future branches.
